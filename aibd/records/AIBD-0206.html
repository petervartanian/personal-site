Wiz finds a critical GitHub RCE with Claude Code and IDA MCP

went from idea to working exploit in under 48 hours

Wiz's AI-aided reverse engineering found a critical GitHub RCE (CVE-2026-3854); github.com was patched the same day, no exploitation found.

What happened

On 4 March 2026 Wiz Research reported to GitHub a critical remote code execution flaw, later CVE-2026-3854, in GitHub's internal git infrastructure: git push options were not sanitized before being written into internal headers, so any authenticated user could run arbitrary commands on GitHub's servers with a single git push. Wiz says AI-augmented tooling, particularly automated reverse engineering of GitHub's compiled binaries with IDA MCP, made the research feasible; The Register reports that the team used Claude Code and went from idea to working exploit in under 48 hours. GitHub reproduced the bug within 40 minutes, deployed a fix to github.com at 7:00 pm UTC that day, released GitHub Enterprise Server patches from 10 March, and found no exploitation.

What it was built to do. Claude Code is Anthropic's agentic coding tool, built to read a codebase, edit files, run commands and connect to external tools over MCP; Wiz used it, with IDA MCP, to automate reverse engineering of GitHub's compiled binaries. Analyzing code for flaws is within that general purpose, so the benefit was an application of what the tool was built to do rather than a departure from it.

Who benefited

  • 2
    organizational

    GitHub closed a critical remote code execution hole in its git push pipeline within hours of the report (fix on github.com at 7:00 pm UTC on 4 March 2026) and shipped patches for six GitHub Enterprise Server release lines; Wiz earned what GitHub calls one of the highest rewards in the history of its Bug Bounty program. The loss avoided is hypothetical: GitHub's forensic investigation found that no other account had triggered the code path and no customer data was accessed, modified or exfiltrated, so the benefit is an exposure closed rather than a demonstrated loss prevented.

The system's part

The AI's documented contribution is speed of analysis, on the researchers' own account. Wiz writes that AI-augmented reverse-engineering tooling, particularly IDA MCP, let it rapidly analyze GitHub's compiled binaries and reconstruct internal protocols at a speed that would not have been feasible manually, and Sagi Tzadik told Dark Reading that with AI tools it took under 48 hours from idea to working exploit; The Register adds that the team used Claude Code 'to take a lot of the legwork out of the process'. The hypothesis, the exploit, the report and the fix were human work: six named Wiz researchers confirmed RCE on GHES 3.19.1 and wrote what GitHub called a thorough report, and GitHub's security and engineering teams reproduced the bug within 40 minutes and deployed the fix. GitHub's own post, the CVE record and the GHES release notes describe a Bug Bounty report without mentioning AI, so the AI-assistance claim rests on Wiz and on outlets quoting Wiz; Wiz's write-up, in the text as fetched, names IDA MCP and not Claude.

Replication

No attempt to repeat it has been recorded.

What produced it

  • A closed-source target that researchers could obtain and disassemble: GitHub's backend git services are also shipped as GitHub Enterprise Server binaries, which gave automated reverse engineering something to work on and a place (GHES 3.19.1) to confirm the exploit.
  • AI-augmented tooling for reverse engineering: IDA MCP (per Wiz) driven by Claude Code (per The Register), used to reconstruct internal protocols and trace where user input could influence server behavior across the pipeline.
  • Experienced vulnerability researchers (six named Wiz authors) to form the hypothesis, build and confirm a working exploit, and write what GitHub called a thorough report that clearly demonstrated the impact.
  • A beneficiary with a Bug Bounty intake and an on-call security team: GitHub reproduced the bug within 40 minutes of the report and deployed a fix to github.com at 7:00 pm UTC the same day.

What must hold again

  • AI output has to be verified by exploit, not trusted: Wiz confirmed RCE on a GHES 3.19.1 instance before reporting, which is why GitHub could validate the report in 40 minutes.
  • The receiving organization must be able to patch its own service and ship fixes to self-hosted customers; GHES customers stayed exposed until they upgraded to the patched versions released from 10 March 2026.
  • Disclosure must wait for the patches (here 4 March to 28 April 2026); and because no exploitation had occurred, the benefit is an exposure closed, not a loss recovered.
