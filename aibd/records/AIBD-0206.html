Wiz uses Claude Code and IDA MCP to find a critical flaw in GitHub

Wiz researchers used Claude Code and IDA MCP to reverse engineer GitHub's binaries and found a critical remote code execution flaw, which GitHub fixed on github.com the same day.

  • 2 an organization

    GitHub closed a remote code execution hole in its git push pipeline within hours of the report. The fix reached github.com at 7:00 pm UTC on 4 March 2026. GitHub also shipped patches for six GitHub Enterprise Server release lines. Wiz earned what GitHub calls one of the highest rewards in the history of its Bug Bounty program. The loss avoided is hypothetical. GitHub's forensic investigation found that no other account had triggered the code path, and CISA records no exploitation. Wiz wrote that its data showed that 88% of GitHub Enterprise Server instances were still vulnerable when it published on 28 April 2026, so many self-hosted servers stayed exposed. NIST rates the flaw High (8.8).

The AI's documented contribution is speed of analysis, on the researchers' own account. Wiz writes that AI-augmented reverse-engineering tooling, particularly IDA MCP, let it rapidly analyze GitHub's compiled binaries and reconstruct internal protocols. Wiz says that speed would not have been feasible manually. Sagi Tzadik told Dark Reading that with AI tools it took under 48 hours from idea to working exploit. The Register adds that the team used Claude Code “to take a lot of the legwork out of the process”. The hypothesis, the exploit, the report and the fix were human work. Costs and harms
The AI tools reduced the effort of investigating opaque binaries, and the same capability can shorten the time that attackers need to find exploitable flaws. In the linked incident 1263, a state-linked operator reportedly used Claude Code against roughly 30 targeted organizations. The protective outcome here depended on private reporting and on GitHub's patches.

What happened

On 4 March 2026, Wiz Research reported a critical remote code execution flaw to GitHub, later numbered CVE-2026-3854. The flaw sat in GitHub's internal git infrastructure. Git push options were not sanitized before being written into internal headers. Any authenticated user could therefore run arbitrary commands on GitHub's servers with a single git push. Wiz says that AI-augmented tooling made the research feasible, particularly automated reverse engineering of GitHub's compiled binaries with IDA MCP. The Register reports that the team used Claude Code and went from idea to working exploit in under 48 hours. GitHub reproduced the bug within 40 minutes and deployed a fix to github.com at 7:00 pm UTC that day. It released patches for GitHub Enterprise Server from 10 March 2026. The National Vulnerability Database entry, published on 10 March 2026, scores the flaw 8.8 (High) under version 3.1 of the Common Vulnerability Scoring System. On 28 April 2026, GitHub disclosed the flaw and reported that its forensic investigation found no exploitation beyond the researchers' own testing. The same day, the Cybersecurity and Infrastructure Security Agency recorded no known exploitation in its enrichment of the entry. Wiz published its own account that day and wrote that its data showed that 88% of GitHub Enterprise Server instances were still vulnerable.

Details

AI system

Role

The tools analyzed compiled binaries and helped researchers reconstruct internal protocols.

Configuration

Wiz used IDA MCP to analyze GitHub’s compiled binaries. The Register identified Claude Code as the tool through which researchers performed some of that work.

Editor’s note. Wiz’s original report names IDA MCP but not Claude Code. The latter identification comes from The Register’s reporting (references 4 and 5).

Autonomy

The AI tools assisted analysis of compiled binaries. Researchers tested and disclosed the exploit, and GitHub engineers independently reproduced and fixed it.

Workflow

A closed-source target that researchers could obtain and disassemble. GitHub's backend git services also ship as GitHub Enterprise Server binaries. Those binaries gave automated reverse engineering something to work on, and GHES 3.19.1 gave a place to confirm the exploit. AI-augmented tooling for reverse engineering: IDA MCP (per Wiz) driven by Claude Code (per The Register). It reconstructed internal protocols and traced where user input could influence server behavior across the pipeline. Experienced vulnerability researchers: six named Wiz authors formed the hypothesis and built and confirmed a working exploit. They wrote what GitHub called a thorough report that clearly demonstrated the impact. A beneficiary with a Bug Bounty intake and an on-call security team. GitHub reproduced the bug within 40 minutes of the report. It deployed a fix to github.com at 7:00 pm UTC the same day.

Human oversight

Wiz researchers developed and tested the exploit. GitHub’s security and engineering teams reproduced the vulnerability and deployed the fix.

AI contribution

Wiz researchers used AI tools to analyze GitHub’s compiled software and reconstruct its internal protocols. They reported that the tools accelerated the work and that they produced a working exploit in under 48 hours.

Follow-up

Conditions for replication

AI output has to be confirmed by exploit, not trusted. Wiz confirmed RCE on a GHES 3.19.1 instance before reporting. That is why GitHub could validate the report in 40 minutes. The receiving organization must be able to patch its own service and ship fixes to self-hosted customers. GHES customers stayed exposed until they upgraded to the patched versions released from 10 March 2026. Disclosure must wait for the patches, here from 4 March to 28 April 2026. No exploitation had occurred, so the benefit is an exposure closed, not a loss recovered.

Purpose

Claude Code is Anthropic's agentic coding tool, built to read a codebase, edit files, run commands and connect to external tools over MCP. Wiz used it, with IDA MCP, to automate reverse engineering of GitHub's compiled binaries. Analyzing code for flaws is within that general purpose. The benefit was an application of what the tool was built to do rather than a departure from it.
