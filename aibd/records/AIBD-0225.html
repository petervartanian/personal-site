SQLite fixes a flaw that Google's Big Sleep agent helped isolate

Google says that its Big Sleep agent, given signs that attackers were preparing to exploit an unknown flaw, isolated SQLite flaw CVE-2025-6965, which SQLite fixed in version 3.50.2 on 28 June 2025.

  • 2 an organization

    SQLite fixed the flaw in version 3.50.2 before any public report of exploitation. Its release log describes the fix: SQLite raises an error early when the number of aggregate terms in a query exceeds the maximum number of columns.

  • Not rated society

    No source documents an outcome for users beyond the patch. Only Google claims that the fix stopped a planned exploitation.

What happened

The SQLite developers state that the flaw was fixed on 27 June 2025 and that it needs an attacker who can inject arbitrary SQL into an application. The SQLite 3.50.2 release carrying the fix is dated 28 June 2025, and SQLite's release log lists the corresponding fix. The Common Vulnerabilities and Exposures record for the flaw, CVE-2025-6965, was published on 15 July 2025. The CVE record, assigned by Google, credits Vlad Stolyarov of Google's Threat Analysis Group with assistance from Google Big Sleep. Google's post of the same day says that, based on intelligence from Google Threat Intelligence, the Big Sleep agent discovered an SQLite vulnerability known only to threat actors. The post says that it was at risk of being exploited. A Google spokesperson told The Record that its threat intelligence group found artifacts indicating that a zero-day was being staged but could not identify the vulnerability. The spokesperson said that Big Sleep was used to isolate it. Google declined to name the actors or describe the indicators. No independent source confirms that exploitation was imminent. The claim rests on Google. On 11 August 2025 the Big Sleep team reported a curl vulnerability, later published as CVE-2025-9086, which curl's maintainer confirmed. As of 28 October 2026 the CVE is not in the catalog of known exploited vulnerabilities kept by the Cybersecurity and Infrastructure Security Agency.

Details

AI system

Inputs and outputs

Human threat analysts supplied partial artifacts, and Big Sleep helped isolate the corresponding SQLite vulnerability.

Workflow

Threat-intelligence artifacts narrowing the target without identifying the bug. An LLM agent with code navigation, sandboxed execution and debugging tools pointed at a specific codebase. A responsive upstream maintainer shipping a fix before disclosure.

Human oversight

Human researchers handled attribution and disclosure, and SQLite maintainers released the fix in version 3.50.2.

Conditions for replication
