Big Sleep may have isolated SQLite zero-day CVE-2025–6965

Google says Big Sleep, fed indicators that attackers were staging a zero-day, isolated SQLite CVE-2025–6965; SQLite shipped the fix in 3.50.2 on 28 June 2025, announced 15 July 2025.

ⓘ

What happened

The SQLite 3.50.2 release carrying the fix is dated 28 June 2025. The CVE record was published 15 July 2025. Google's post says that, based on intel from Google Threat Intelligence, the Big Sleep agent discovered an SQLite vulnerability known only to threat actors. It was at risk of being exploited, the post says. A Google spokesperson told The Record that its threat intelligence group found artifacts indicating a zero-day was being staged but could not identify the vulnerability. Big Sleep was used to isolate it, the spokesperson said. Google declined to name the actors or describe the indicators. The CVE record, assigned by Google, credits Vlad Stolyarov of Google's Threat Analysis Group with assistance from Google Big Sleep. SQLite's release log lists the corresponding fix. Independent confirmation that exploitation was imminent is absent. The claim rests on Google.

Purpose. Actively search for and find unknown security vulnerabilities in software using a large language model (LLM) agent (Google DeepMind and Project Zero).

AI’s contribution

Per Google's spokesperson, human threat analysts supplied limited indicators and Big Sleep isolated the specific vulnerability. The CVE credit names a human finder “with assistance from Google Big Sleep”. Developer and the organization reporting the benefit are the same company. The Record and the SQLite release log are the independent sources. Neither confirms the threat-actor staging.

Further evidence

Setting. Threat-intelligence artifacts narrowing the target without identifying the bug. An LLM agent with code navigation, sandboxed execution and debugging tools pointed at a specific codebase. A responsive upstream maintainer shipping a fix before disclosure.

Conditions. Partial indicators of a staged exploit must exist and be shared with the agent's operators. Target code must be small enough for the agent to reason over. Coordinated disclosure before the actor's exploitation window.
