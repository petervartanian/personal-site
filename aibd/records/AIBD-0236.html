OpenAI o3 finds CVE-2025–37899, a use-after-free in ksmbd

Sean Heelan, benchmarking o3 on ksmbd with no scaffolding, had the model surface an unknown use-after-free in the SMB logoff handler; the kernel CNA published CVE-2025–37899 on 20 May 2025.

ⓘ

What happened

Heelan's write-up followed on 22 May 2025. Heelan is an independent vulnerability researcher auditing ksmbd (the Linux kernel's in-kernel SMB3 server). He used a known bug (CVE-2025–37778) to benchmark OpenAI's o3 via the plain application programming interface (API), with no scaffolding, agents or tools. Given about 12,000 lines covering all SMB command handlers, o3 reported a previously unknown use-after-free in the handler for the SMB “logoff” command. sess->user can be freed while another connection bound to the same session still uses it. The Linux kernel CNA's record describes the fix (“ksmbd: fix use-after-free in session logoff”) with commits in five stable branches. Linuxiac reports the upstream response was fast and patches were merged for every maintained branch.

Heelan calls it, to his knowledge, the first public case of a large language model (LLM) finding a vulnerability of that nature.

Purpose. General-purpose reasoning model used by the researcher to audit kernel source code for vulnerabilities.

AI’s contribution

The model produced the finding unprompted during a benchmark. Heelan selected the code, validated the report and handled disclosure. He notes the model also produced false positives in other runs. The account is the independent deployer's own, corroborated by the CVE record and third-party coverage, not by OpenAI.

Beneficiaries

  • society

    A remotely reachable kernel memory-safety bug was fixed across maintained branches before any reported exploitation. Exposure of ksmbd users is not quantified.

  • an organization

    The kernel project received a report with a fix merged quickly, per Linuxiac.

Further evidence

Setting. A code slice under roughly 10k-12k lines chosen by an expert. Repeated model runs with reports triaged by a human. A maintainer workflow that accepts and patches reports quickly.

Conditions. Expert curation of context and validation of candidate bugs. Tolerance for false positives across runs.
