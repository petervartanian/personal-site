Code Intelligence's Spark finds a heap use-after-free in wolfSSL

Spark, an AI fuzz-test agent, found a heap use-after-free in wolfSSL in late Oct 2024; fixed in PR 8139 and shipped in 5.7.6 on 31 Dec 2024.

What happened

Spark, the AI test agent in Code Intelligence GmbH's CI Fuzz product, was run on wolfSSL, an open-source cryptography library for embedded and IoT devices, in its final beta test in late October 2024. By the vendor's account, after one command the agent chose the target, generated and ran a fuzz test, and exposed a heap use-after-free in pem_read_bio_key(), where a BIO write-back could reallocate a buffer still referenced by a pointer. The vendor reported it to wolfSSL, which merged a fix in PR 8139 on 1 November 2024 and shipped it in release 5.7.6 on 31 December 2024, crediting 'Peter' in the release notes; the vendor's blog post on the find is by its engineer Peter Samarin.

What it was built to do. Spark was built to find bugs and vulnerabilities autonomously by selecting functions to fuzz and generating and running fuzz tests; finding this flaw was exactly that function, exercised in the vendor's own beta test.

Who benefited

  • 2
    organizational

    wolfSSL received a reproducible report of a heap use-after-free in a private-key parsing path and merged the fix within days (PR 8139, 1 November 2024), shipping it in 5.7.6 on 31 December 2024. The maintainers listed it among bug fixes rather than in the release's Vulnerabilities section, no CVE for it appears on wolfSSL's vulnerabilities page, and the vendor itself says the exploit conditions 'don't seem easy to meet', so the benefit is material but bounded.

The system's part

On the vendor's account, Spark selected the target, generated the fuzz test and ran it after a single 'cifuzz spark' command, with one manual step to confirm that the finding was real and exploitable under narrow conditions. wolfSSL's pull request and release notes confirm the bug, its location in pem_read_bio_key(), the timing and the reporter's first name, but mention neither AI nor Code Intelligence; the autonomous discovery therefore rests on the vendor's statements, repeated by QA Financial and SC Media, not on an independent test.

Replication

No attempt to repeat it has been recorded.

What produced it

  • wolfSSL's source tree (before 5.7.6) set up as a CI Fuzz project by the vendor
  • A single 'cifuzz spark' command, after which the agent chose pem_read_bio_key() as a target and generated and ran a fuzz test
  • A sanitizer-detectable heap use-after-free in the BIO write-back path of pem_read_bio_key() that a generated input could trigger
  • A maintainer team that tracked the report as ZD#18875 and merged a fix within three days of the discovery

What must hold again

  • A human must confirm the finding: the vendor says the one manual step was assessing that the bug exists and is exploitable under specific conditions
  • The beneficiary must be an identifiable project with a public fix record; without wolfSSL's PR and release notes the event would rest on vendor claims alone
  • The AI's share of the work is described only by the vendor; wolfSSL's records name the reporter, not the tool, so the autonomy claim cannot be replicated without the vendor's product
