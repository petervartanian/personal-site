What happened

The date is that of maintainer Daniel Stenberg's account. The reports arrived from mid-September 2025. Stenberg writes that a security report received on 16 September accurately identified a possible stack-based buffer overflow in curl's Kerberos FTP code. It was not turned into a CVE only because the code could not be reached. The project then removed krb5-ftp support. The reporter, Joshua Rogers, then forwarded a large list of further potential issues found mostly with ZeroPath, an AI-powered code analyzer. That produced over two hundred possible problems despite curl's existing compilers, static analyzers and fuzzing. From the initial list about 50 separately identifiable bugfixes were merged. Second and third lists of 47 and 158 items followed. Stenberg told The Register that about 50 bugfixes based on Rogers' reports had been merged.

Rogers' retrospective states that about 98% of the curl bugs reported and fixed were discovered by ZeroPath. It puts the running total of fixed bugs around 150.

What it was built to do. AI-powered static analysis of source code to find vulnerabilities and bugs.

The system's part

The maintainer confirms the reports' quality and the merged fixes. He notes he does not know the exact split between tool and human. Rogers attributes ~98% of the fixed curl bugs to ZeroPath. Both the deployer and the confirming maintainer are independent of the vendor.

Replication

What produced it. A large, mature C codebase already covered by conventional analyzers and fuzzing. An expert researcher filtering scanner output before reporting. Maintainers willing to work through long candidate lists.

What must hold again. Human triage to remove false positives. Maintainer capacity to review hundreds of items.
